Fable 2 — проверка текстур и диагностика v1

Это тестовый PowerShell-инструмент для УЖЕ установленной Fable-2-Recomp 1.5.0.
Он не является новой сборкой игры. EXE/DLL/ISO/игровых данных здесь нет.
На Windows инструмент в этой среде НЕ запускался; начните с самопроверки.

УСТАНОВКА
Закройте игру и обычный лаунчер. Отдельно скопируйте папку saves.
Распакуйте содержимое этого ZIP прямо рядом с fable_2.exe, например:
D:\Fable2\Fable 2 1.5.0\

Рядом с fable_2.exe должны появиться:
Fable2-Diagnostic.ps1
START-READBACK-TEST.cmd
START-CURRENT-DIAGNOSTIC.cmd
RUN-SELF-TESTS.cmd
lib\TomlTextDocument.cs
и этот README. Игровые файлы заменять не требуется.

ПРОВЕРКА
1. Запустите RUN-SELF-TESTS.cmd.
   Он проверяет общий редактор TOML, не открывая файлы игры.
   Должно появиться «PASS: 11 parser assertions».
   Если появилась ошибка — не запускайте остальные CMD, пришлите её текст.
2. Запустите START-READBACK-TEST.cmd. В окне подтвердите запуск буквой Y.
   Перед изменением создаётся точная копия настроек.
   В fable2_config.toml меняются ТОЛЬКО две строки секции [patches]:
       realtime_texture_morphing = false
       hero_dog_texture_readback = true
   Дополнительно игра получает аргумент:
       --readback_resolve_force_addresses=0x12704000
   Он задаёт адрес readback только этому процессу и преодолевает конфликт
   с сохранённым пустым значением SDK/окружения для того же параметра.
   Дисковый fable_2.toml инструмент НЕ редактирует.
   Глобальный readback_resolve (none/full/...) не меняется.
3. Окно PowerShell можно свернуть, но не закрывайте его до выхода из игры.
   Загрузите сохранение, проверьте собаку/героя и попробуйте бой.
4. После выхода появится папка:
       diagnostics\session-ДАТА-ВРЕМЯ-ID\
   В ней session.json, config-before, config-start, config-end,
   texture-request.txt, texture-runtime.txt и изменившиеся logs.
   Для диагностики можно упаковать эту папку в ZIP. Перед отправкой
   просмотрите содержимое: конфигурации и журналы содержат локальные пути.
   Сам инструмент ничего не отправляет.

START-CURRENT-DIAGNOSTIC.cmd запускает с текущими настройками:
не изменяет галочки и не добавляет readback-override; только собирает отчёт.
Галочки, ранее сохранённые START-READBACK-TEST.cmd, при этом остаются сохранёнными.

ОТКАТ НАСТРОЕК
Полностью закройте игру и лаунчер.
В папке нужного сеанса лежит config-before\fable2_config.toml.
Можно скопировать его обратно рядом с fable_2.exe, предварительно сохранив
текущий файл. Это восстановит ВЕСЬ файл, включая прочие настройки на момент
резервирования, поэтому не делайте так после последующих полезных изменений.
Альтернатива: выставить только две исходные галочки в обычном лаунчере.
Разовый аргумент readback не применяется при запуске обычным лаунчером.

ОГРАНИЧЕНИЯ
- Инструмент рассчитан на штатный Windows PowerShell 5.1. .NET 8 SDK ему не нужен.
- CMD использует ExecutionPolicy Bypass только для одного процесса;
  системная политика выполнения не меняется.
- Многострочные TOML-строки/коллекции и дубликаты отклоняются без перезаписи:
  редактор сознательно не пытается «угадать» сложную структуру.
- При появлении ошибки после сохранения галочек они уже могут быть изменены:
  резервная копия config-before остаётся доступной.
- Копируются не более 8 изменившихся файлов *.log; для каждого максимум
  последние 32 МиБ. Ротация может включить журнал предыдущего сеанса.
- При закрытии окна PowerShell отчёт останется незавершённым.
- Журналы новой C++-диагностики [texture-runtime] появятся лишь с пересобранным
  игровым EXE; обычная 1.5.0 может не писать их.
- Успех чтения настроек не доказывает, что графический плагин отработал правильно.
- Это проверка альтернативного механизма текстур, а не обещание исправить вылет.
- Сохранения, игровые данные, дампы памяти и бинарники в отчёт не копируются.
- Проверка хеша XEX не отключается; реестр, драйверы и защита Windows не меняются.
